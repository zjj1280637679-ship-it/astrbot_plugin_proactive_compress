# astrbot_plugin_proactive_compress

一个会在对话变长时，把旧内容整理成摘要的 AstrBot 插件。

对话聊久了，上下文越堆越长，到极限时 AstrBot 会在请求内压缩——那一下会让人感到停顿，也会多消耗 token。这个插件把压缩提前到对话用到 **60%** 时，在后台完成：旧内容整理成摘要，放回对话里，主对话不用停下。

---

## 它解决什么问题

- 压缩不用等到 82% 才发生：提前整理，长对话保持干净，也少花 token。
- 压缩在后台进行：对话不用停下来等。
- 管理员可以手动触发：发 `/compress`，或直接说一句"压缩一下上下文"。
- 摘要内容可指定：在设置里填 `emphasis_instruction` 做全局加权；每次触发时也能临时附带要求（见下）。

---

## 当前状态

已经可以正常使用：

- ✅ 后台主动压缩（默认 60% 触发，可调）
- ✅ `/compress` 命令 + 自然语言触发（仅管理员）
- ✅ 摘要加权指令 `emphasis_instruction`
- ✅ 兼容 AstrBot 4.27.x，带自动化测试

边界说明：

- 压缩模型建议指向有免费额度的模型（如火山方舟标准 API 的 `deepseek-v4-pro-ga`），压缩走免费额度，不占用主对话的订阅与缓存。
- 显式缓存（Context API）不支持 `tools`，对工具型 Agent 不适用，本插件不打算硬接。

## 快速开始

1. 把插件目录放进 AstrBot 的 `data/plugins/`
2. Dashboard 插件管理里刷新加载（或重启 AstrBot）
3. 对话用到 60% 时，它会开始自己工作。

想立刻试一下？管理员对 bot 说：

```
压缩一下上下文
```

或者直接发 `/compress`。

**顺带附上本次压缩的额外要求**（只对这次生效，不写进配置）：

```
/compress 重点保留关于装修方案的结论
压缩一下上下文，重点保留今天讨论的问题和解决办法
```

匹配到"压缩/总结/整理 + 上下文/对话/聊天"的意图短语后，后面的内容会被当作本次压缩的额外提示词，和全局 `emphasis_instruction` 一起交给压缩模型。

---

## 常用配置（Dashboard → 插件设置）

| 配置 | 默认 | 一句话说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `trigger_ratio` | `0.6` | 上下文用到多少时后台压缩 |
| `compress_provider_id` | 空 | 用哪个模型压缩；留空沿用 AstrBot 的 `llm_compress_provider_id` |
| `emphasis_instruction` | 空 | 摘要里重点保留什么，例如"之前遇到的问题和解决方式、没做完的事" |
| `nl_enabled` / `nl_patterns` | `true` / 内置 | 自然语言触发开关与识别规则 |
| `command_enabled` | `true` | 是否允许 `/compress` 命令 |

冷却时间、最小消息数、检查延迟等都有合适的默认值，一般不用动。

## 它是怎么做到的

```
主对话:   60% ──> 70% ──> 82%（原生兜底）
                ↑ 对话不停
后台:     在 60% 时拍一个快照 → 用压缩模型把旧内容写成摘要 → 完成后换入
```

几个保证安全的点：

- **替换只是一瞬间**：只在替换那一刻才锁会话（毫秒级），平时不打扰主对话。
- **新消息不会丢**：压缩期间来的新消息，换入时会接到摘要后面。
- **过期的结果作废**：如果压缩完成前上下文已经变了，这份结果直接丢弃，不写回。
- **失败会重试**：压缩失败等 30 秒再试；成功后才进入 5 分钟冷却。

## 给想深入了解的你

- 复用 AstrBot 原生 `LLMSummaryCompressor` 和 `EstimateTokenCounter`，不是另起炉灶。
- 同一对话同时只有一个后台压缩任务，避免重复并行。
- 插件被重载或禁用时，会取消并回收所有后台任务。
- 图片、音频按多模态策略计数，不会把 base64 当普通文字算。

## 测试
