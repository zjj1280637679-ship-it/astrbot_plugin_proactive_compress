# astrbot_plugin_proactive_compress

一个会**自己悄悄帮你整理对话**的 AstrBot 插件。

对话聊久了，上下文越堆越长——到了极限，AstrBot 要么卡一下开始压缩，要么多烧不少 token。这个插件会在对话还没到那一步之前（默认用到 **60%** 时），在后台把旧内容整理成摘要、悄悄换进去。你和群友几乎感觉不到它存在：**对话不中断、新消息不丢、不用手动操作**。

---

## 它帮你解决什么

- **主对话不停机**：压缩在后台进行，不再"聊到一半卡住等压缩"。
- **上下文始终干净**：不用等 82% 才被迫压缩，提前整理，长对话更稳也更省钱。
- **管理员说了算**：可以发 `/compress`，也可以直接说一句"压缩一下上下文"，它都会照做。
- **记得你在意的内容**：告诉它"摘要里多保留之前遇到的问题、没做完的事"，它会按你说的保留。

---

## 现在是什么状态

已经可以正常使用：

- ✅ 后台主动压缩（默认 60% 触发，可调）
- ✅ `/compress` 命令 + 自然语言触发（仅管理员）
- ✅ 摘要加权指令 `emphasis_instruction`
- ✅ 兼容 AstrBot 4.27.x，带自动化测试

边界与说明：

- 压缩模型建议指向有免费额度的模型（比如火山方舟标准 API 的 `deepseek-v4-pro-ga`），压缩走免费额度、不占用主对话的订阅与缓存。
- 显式缓存（Context API）不支持 `tools`，对工具型 Agent 不适用，本插件不打算硬接。

---

## 快速开始

1. 把插件目录放进 AstrBot 的 `data/plugins/`
2. Dashboard 插件管理里**刷新加载**（或重启 AstrBot）
3. 完事——对话用到 60% 时，它就开始自己工作了。

想立刻试一下？管理员对 bot 说：

```
压缩一下上下文
```

或者直接发 `/compress`。

## 常用配置（Dashboard → 插件设置）

| 配置 | 默认 | 一句话说明 |
|---|---|---|
| `enabled` | `true` | 总开关 |
| `trigger_ratio` | `0.6` | 上下文用到多少时后台压缩 |
| `compress_provider_id` | 空 | 用哪个模型压缩；留空沿用 AstrBot 的 `llm_compress_provider_id` |
| `emphasis_instruction` | 空 | 摘要里特别保留什么，例如"之前遇到的问题和解决方式、没做完的事" |
| `nl_enabled` / `nl_patterns` | `true` / 内置 | 自然语言触发开关与识别规则 |
| `command_enabled` | `true` | 是否允许 `/compress` 命令 |

冷却时间、最小消息数、检查延迟等都有合适的默认值，一般不用动。

## 它是怎么做到的（简单版）

```
主对话:   60% ──> 70% ──> 82%（原生兜底）
                ↑ 你感觉不到
后台:     在 60% 时拍个快照 → 用压缩模型把旧内容写成摘要 → 完成后一瞬间换入
```

几个保证安全的点：

- **换入是一瞬间的事**：只在替换那一刻才锁会话（毫秒级），平时完全不打扰主对话。
- **新消息不会丢**：压缩期间来的新消息，换入时会自动接到摘要后面。
- **过期结果直接扔**：如果压缩完成前上下文已经变了（比如原生压缩先动了），这份结果作废，绝不乱写。
- **失败不折腾**：压缩失败等 30 秒再试；真正成功后才进入 5 分钟冷静期。

## 给爱钻研的你

- 复用 AstrBot 原生 `LLMSummaryCompressor` 和 `EstimateTokenCounter`，不是另起炉灶。
- 同一对话同时只有一个后台压缩任务，杜绝重复并行。
- 插件被重载或禁用时，会取消并回收所有后台任务。
- 图片、音频按多模态策略计数，不会把 base64 当普通文字算。

## 测试

插件自带一套**不花钱、不连真机**的自动化测试（用假的会话管理 + 真实 AstrBot 组件），覆盖并发合流、陈旧作废、多模态计数、生命周期清理等场景。CI 会在每次 push 时自动跑。

## 兼容性

AstrBot `>=4.27,<5`，依赖 `session_lock_manager`、`LLMSummaryCompressor`、`EstimateTokenCounter` 等当前 AstrBot 组件。
